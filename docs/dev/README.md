# Developer documents

Read in this order:

1. [features.md](features.md): what exists and where the code is, with a status per area.
2. [testing.md](testing.md): how the project is tested, the commands, what a pass looks like, and what to run before sending a change.
3. [test-results.md](test-results.md): what was measured and verified, with conditions, the evidence level of each result, what was not verified, and the limits found by testing.
4. [fonts.md](fonts.md): how the UI fonts are built from their sources and how to add characters.
5. [release.md](release.md): how a release is built and checked.

The repository layout and the rules that matter (vendored code, generated files, credentials, flashing) are in `AGENTS.md` at the top level.
